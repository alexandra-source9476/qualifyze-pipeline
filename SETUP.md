# Setup & Run (macOS)

This is a how-to for running the pipeline locally and pushing the repo to
GitHub. The README.md (next to this file) contains the design discussion.

## 1. Prerequisites

- macOS with Python 3.10 or 3.11 (3.12+ also works).
- Git installed (`git --version` should print something).

```bash
python3 --version
git --version
```

## 2. Clone (or open) the project

If a teammate gave you a GitHub link:

```bash
git clone https://github.com/<user>/qualifyze_pipeline.git
cd qualifyze_pipeline
```

If you already have it locally, just `cd ~/Desktop/Q/qualifyze_pipeline`.

## 3. Place the Excel

```bash
mkdir -p data/raw
# copy your export here, exact filename is not required
cp ~/Downloads/searchGMPCExport_*.xls data/raw/
```

## 4. Create a virtualenv and install deps

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

## 5. Regenerate the static master (only once per Excel)

`gold_master_site.sql` is fully static (hardcoded INSERTs). Five rows in it
need OMS Location IDs that actually appear in your Excel so that Pass 1
(exact match) produces visible results. The repo ships with placeholder OMS
IDs; replace them by running:

```bash
python scripts/regenerate_master.py data/raw/searchGMPCExport_*.xls
```

The script overwrites `dbt_project/models/gold/gold_master_site.sql` in place
with 5 real OMS IDs from your Excel + 5 hardcoded EU mock sites. Commit the
result so the next person doesn't have to redo it.

## 6. Run the pipeline

```bash
python run_pipeline.py --source eudragmdp --file data/raw/searchGMPCExport_*.xls
```

You should see, in order:

1. `Starting pipeline run: run_YYYYMMDD_HHMMSS (source=eudragmdp)`
2. `[ingest] engine=xlrd, header_row=4` (or `openpyxl`/`5` for .xlsx)
3. `[ingest] N rows read; appending to raw_eudragmdp ...`
4. `dbt seed` -> `dbt run --select bronze` -> 2 models PASS
5. `dbt run --select silver gold_master_site` -> 3 models PASS
6. `[matching] Pass 1 (exact ...): X matches`
7. `[matching] Pass 2 (fuzzy ...): Y matches`
8. `dbt run --select gold (post-matching)` -> 3 models PASS
9. `dbt test (informational)` -> tests run, only the singular duplicate test
   fails when there is a duplicate in the current batch
10. `Pipeline complete. batch_id=run_...`

## 7. Inspect the warehouse

```bash
sqlite3 data/qualifyze.db
```

```sql
.tables
SELECT COUNT(*) FROM raw_eudragmdp;
SELECT COUNT(*) FROM bronze_eudragmdp;
SELECT COUNT(*) FROM bronze_rejected;
SELECT match_confidence, COUNT(*) FROM silver_eudragmdp_sites GROUP BY 1;
SELECT * FROM gold_master_site;
SELECT COUNT(*) FROM gold_site_compliance_view;
SELECT * FROM gold_ncr_alerts LIMIT 5;
SELECT raw_row, rejection_reason FROM bronze_rejected LIMIT 5;
.quit
```

## 8. Run the test fixture (small Excel with edge cases)

```bash
python scripts/generate_test_excel.py
rm -f data/qualifyze.db
python run_pipeline.py --source eudragmdp --file data/raw/test_data.xlsx
```

The test fixture has 5 rows and is engineered to trigger rejection paths and
the duplicate test. See `scripts/generate_test_excel.py` for what each row
exercises.

## 9. Push to GitHub

### 9a. Create the repo on GitHub

1. https://github.com/new
2. Name: `qualifyze_pipeline`, Visibility: Private (recommended).
3. Do NOT add README/.gitignore/license - they exist in the repo.
4. Create. Note the URL.

### 9b. Initialise locally and push

From the project root:

```bash
git init
git add .
git commit -m "Initial commit: EudraGMDP medallion pipeline"
git branch -M main
git remote add origin https://github.com/<user>/qualifyze_pipeline.git
git push -u origin main
```

If GitHub asks for a password and rejects it, generate a Personal Access
Token (https://github.com/settings/tokens, scope `repo`) and use it instead.
Or set up SSH (`ssh-keygen -t ed25519` -> add the .pub at
https://github.com/settings/keys -> use the `git@github.com:...` URL).

### 9c. .gitignore notes

`data/qualifyze.db` is excluded (it's regenerated by the pipeline). The
`.xls` is NOT excluded. If your data is sensitive add this line to
`.gitignore` before the first commit:

```
data/raw/*.xls
data/raw/*.xlsx
```

Then teammates will need to provide the Excel file out-of-band before they
can run the pipeline.

## Troubleshooting

- `xlrd.biffh.XLRDError: Excel xlsx file; not supported` -> the file is
  `.xlsx`. Ingest auto-detects this since v2; if you still see this error,
  check the file magic bytes manually.
- `dbt debug` says `unable to open database file` -> the relative path
  `data/qualifyze.db` is resolved from the project root. Run from there or
  export `QUALIFYZE_DB_PATH=$PWD/data/qualifyze.db`.
- `dbt: command not found` -> activate the venv: `source .venv/bin/activate`.
- `Compilation Error: ... source 'raw.raw_eudragmdp' which was not found` ->
  `models/sources.yml` got moved out of `models/`; restore it.
